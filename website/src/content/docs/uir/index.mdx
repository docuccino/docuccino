The **UIR** (Universal Intermediate Representation) is the document Docuccino builds internally and
can export directly (`--format=uir`). It's an OpenAPI-shaped JSON document with a little extra: a
stable identity for every operation and schema, a record of where each detail came from, and a
guarantee that identical code always produces identical bytes.

You never *have* to look at the UIR — the OpenAPI export is what you'll usually ship. But it's the
foundation for Docuccino's deterministic output and semantic diff, and it's a clean input for richer
tooling (changelogs, mock servers, AI agent tool schemas) that wants more than plain OpenAPI offers.

<Aside type="note">
A UIR document is a valid OpenAPI document plus one reserved key, `x-docuccino`, allowed on any node.
Exporting OpenAPI simply strips and remaps that key — so nothing is lost in translation.
</Aside>

## Shape

```json
{
  "$schema": "https://spec.docuccino.app/uir/1.0/schema.json",
  "uir": "1.0.0",
  "openapi": "3.2.0",
  "info": {}, "servers": [], "security": [], "tags": [],
  "paths": {}, "webhooks": {},
  "components": { "schemas": {}, "responses": {}, "parameters": {}, "securitySchemes": {} },
  "x-docuccino": {
    "document": { "id": "doc:default", "contentHash": "…" },
    "content": { "pages": [] },
    "diagnostics": []
  }
}
```

There are **no timestamps anywhere** — they'd break determinism, so the format forbids them.
Consumers are expected to ignore `x-docuccino` members they don't recognize, which lets the format
grow without breaking older readers.

## Stable identities

Every operation, parameter, named schema, and response carries an `x-docuccino.id`. Identities are
computed from meaning, never from file paths or line numbers, so they survive refactors:

| Kind | Built from | Survives | Changes when |
| --- | --- | --- | --- |
| `op:` | method + path template (params normalized) | file moves, controller/method renames, path-param renames | the URL or method changes |
| `par:` | operation + location + name | reorder, description edits | the parameter is renamed |
| `sch:` (named) | class name (pin with `#[SchemaId]`) | file moves | the class is renamed without a pin |
| `sch:` (inline) | the schema's structure | prose edits | the shape changes |
| `res:` | operation + status + media type | — | the status changes |

This is what makes a meaningful diff possible: rename a controller and nothing changes; change a URL
and the diff shows exactly that operation removed and added.

## Deterministic output

The format specifies a canonical ordering and serialization — fixed member order, sorted map keys, a
fixed order of HTTP methods, 2-space indentation, and a trailing newline. The result:

## Provenance

Each contribution to the document is recorded — what produced it, which fields it set, and the
source location — so tooling (and you) can answer "why is this documented this way?":

```json
{
  "producer": "integration:query-builder",
  "fields": ["schema", "description"],
  "source": { "file": "app/Http/Controllers/InvoiceController.php", "line": 28 },
  "confidence": 0.9,
  "overrode": [ { "field": "description", "producer": "inference" } ]
}
```

When a higher-precedence layer wins a field, the value it replaced is kept in `overrode` rather than
discarded. Control how much provenance is emitted with `--provenance=none|winners|full`.

## Content layer

Point [`content.dir`](/reference/configuration/#content) at a folder of Markdown and Docuccino
compiles it into the document: guide pages with stable ids, plus a navigation tree derived from your
folder structure (overridable in frontmatter). Reference operations and schemas directly from your
prose with directives, and Docuccino resolves them at build time:

```markdown
See ::operation{id="invoices.index"} for pagination, which returns ::schema{name="InvoiceData"}.
```

A directive that points at something that doesn't exist becomes a diagnostic — so your guides can't
silently drift from your API. Because narrative lives in the document, prose changes show up in the
diff and changelog too, not just API changes.
